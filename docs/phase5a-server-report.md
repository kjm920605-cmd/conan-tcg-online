# Phase 5A Server implementation report

Implemented `src/server/managers.ts`, `src/server/index.ts`, and `apps/server/index.ts`; regression tests in `tests/server.test.ts`.

Factory: `await createGameServer({content, port?, host?, matchOptions?, rng?})` returns `{port, manager, close():Promise<void>}`. Defaults localhost:8787; port 0 supports ephemeral real WebSocket tests. `manager.inspectMatch(matchId)` is trusted host-only read access to `{state,stateVersion}` and has no network message equivalent. App entry loads the same content catalog, uses fixed Fixture Deck A/B, a server-generated random seed and UUID match identity. `PORT` and `HOST` configure local development hosting.

RoomManager binds server-generated UUID session and 32-byte random resume token to each connection. Tokens are emitted only in that session's SESSION message. Joining never restores a seat. Resume validates identity/token, replaces connection binding synchronously, revokes old connection before closing it, and projects the restored seat. Old close events cannot disconnect the replacement. Disconnect and explicit in-match leave preserve match and seat; prematch leave releases seat and invalidates old credentials.

MatchManager uses the original GameEngine and original player projection/legal action/decision functions. Accepted transactions use an isolated trusted engine restore, dispatch, bounded automatic continuation, and commit. No rules, card definitions, rule questions, or auto-pass semantics are introduced. Unexpected auto continuation errors or the 2000-step limit reject without committing the draft. Version increments once per accepted transaction. Exact full-envelope command fingerprints and actor identity are stored separately from engine revision. Session and match authentication precede receipts; duplicate receipts precede stale-version checks. Explicit decision ownership and identity checks apply to intent regardless of message type.

Transport validates ClientMessageSchema and all ServerMessageSchema messages, rejects malformed/binary/unknown payloads without raw errors, limits frames to 64 KiB, and handles ws errors without crashing the process. Engine diagnostics are reduced to codes; projections never expose raw snapshot, RNG, hidden card identity, free-form engine event details, or another player's decision candidates. Runtime storage is process-local, with no persistence or production account/rate-limit infrastructure.

Verification: initial test failed with missing src/server/index.ts (red), followed by implementation and green. `node --import tsx --test tests/server.test.ts`: 3/3 pass. Covered full room, readiness, ownership despite GAME_COMMAND choice envelope, stale choice, stale version + resync, duplicate exact command no state/RNG movement, changed envelope rejection, cross-actor receipt rejection, match mismatch before cached ack, token rejection/replacement, old socket closure, disconnect preservation, midmatch seat exclusion, prematch leave credential invalidation, private hands/waiting decision, malformed/spoofed fields, oversized frame close 1009, and subsequent server usability.

No logging includes tokens or gameplay snapshots. No engine source was changed. Full project verification remains the parent task's integration gate.
